- **Never hard-code secrets or credentials (connection strings, passwords, API keys, tokens, signing keys) in source or committed configuration; load them from a secure configuration source.** Committed secrets leak to everyone with read access and can't be rotated without a code change. *Check:* Look for credential literals in code, appsettings*.json, *.config, chart values or workflows. <sub>NCodeGroup maintainer: principal-engineer-review</sub>
- **Don't add an option that disables or relaxes a security control (CSRF checks, callback binding, cookie attributes, return-URL or proxy allow-lists, token signing or key-role checks); a setting may only select an equal or stronger behavior, and every library default must be safe.** A library that is correct by default with no off switch can't be weakened by misconfiguration; defaults may be permissive only where the caller's policy is unknown, never where that opens a gap. *Check:* Look for new boolean or enum options such as `DisableCsrf`, `SameSite=None`, wildcard allow-lists, or validation defaults that accept unsigned tokens, decrypt with a verification key, or skip a check the caller stated. <sub>Identity docs/backend-for-frontend.md; Identity ADR-1154</sub>
